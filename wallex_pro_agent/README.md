# Wallex Pro Agent — بسته مستقل کامل برای تست

## وضعیت بسته
این بسته شامل کد یکپارچه و آزمون‌های آفلاین است؛ تضمین سود، رتبه مسابقه یا تأیید نهایی پول واقعی نیست.
کلید واقعی، فایل .env، دیتابیس یا موجودی قدیمی داخل ZIP نیست. پیش‌فرض LIVE غیرفعال است.
توابع سیگنال از فایل wallex_pro_backtest.py ارسالی استخراج شده‌اند. نسخه بدون کلید منبع در reference/original_sanitized.py برای مقایسه نگه‌داری شده است.
پارامترها: V2=BB192/2.0، FAST=BB64/1.8، RSI ورود۲۸؛ آستانه BTC/ETH=31.5 و بقیه۳۰؛ خروج RSI14>=75 یا باند متعلق به دنده ورود. cooldown۴۸کندلی و فیلترها حفظ شده‌اند.
COMBINED هنگام ورود هم‌زمان V2 را انتخاب می‌کند؛ origin پوزیشن ثابت و خروج مستقل است. ترتیب DOGE، XRP، ETH، SOL، BTC است.
آزمون برابری، فرمول‌ها را روی ورودی یکسان می‌سنجد؛ اجرای زنده با تأخیر، اسپرد و fills برابر با پرشدن ایده‌آل کندل نیست.

## ۱. استخراج و تست آفلاین
ZIP را در پوشه‌ای جدا با نام wallex_pro_agent استخراج کنید؛ روی پروژه قبلی کپی نکنید.

```bat
conda activate finance
cd /d C:\Users\LENOVO\Desktop\Mosabeghe\wallex_pro_agent
python -m pip install -r requirements.txt
python test_all.py
```

خروجی موفق ALL_TESTS_PASS است. نتیجه دقیق و تعداد تست‌ها در reports/selftest_results.json ثبت می‌شود.
تست‌ها شبکه واقعی را مسدود و دیتابیس موقت استفاده می‌کنند. نیاز به کلید ندارند.

## ۲. کلیدها فقط در فایل محلی

```bat
if not exist .env copy .env.example .env
notepad .env
```

کلید جدید والکس و BoxAPI را وارد کنید. کلید افشاشده قدیمی را تعویض کنید. کلید والکس باید برای حساب هکاتون و دارای خواندن/معامله باشد؛ برداشت لازم نیست.
فایل env از KEY=value ساده و مقادیر داخل کوتیشن پشتیبانی می‌کند؛ اجرا یا interpolation ندارد. متغیر محیطی سیستم اولویت دارد.
هیچ env یا دیتابیسی را در GitHub قرار ندهید.

## ۳. آزمون شبکه فقط‌خواندنی

```bat
python wallex_live_agent.py --mode probe --test-ai
```

مشخصات، کارمزد فعلی، عمق پنج‌سطحی، موجودی و سفارش‌های باز خوانده می‌شوند. یک تست واقعی مدل انجام می‌شود؛ هیچ سفارش ارسال نمی‌شود. تست مدل اعتبار مصرف می‌کند.
خروجی مدل برای SELF_TEST باید SKIP_FAKEOUT و model_ok=true باشد.

## ۴. Shadow

```bat
python -u wallex_live_agent.py --mode shadow --once
python -u wallex_live_agent.py --mode shadow
```

سرمایه مجازی پنج میلیون و دفتر جدا از LIVE است. حالت once یک چرخه است و می‌تواند پوزیشن مجازی باز باقی بگذارد.
پرشدن Shadow از پنج سطح واقعی اوردربوک با سقف/کف قیمت Limit شبیه‌سازی می‌شود؛ باقی‌مانده فوراً لغوشده فرض می‌شود. این تقریب IOC محلی است، نه بازسازی صف یا پاسخ صرافی.
کارمزد Shadow تومانی فرض می‌شود. LIVE ارز واقعی کارمزد را از fills می‌خواند.
اگر ورود نباشد AI فراخوانی نمی‌شود؛ این خطا نیست.

## ۵. داده و تطبیق با مرجع
مسیر کش قبلی را در REFERENCE_CACHE_DIR بنویسید یا فقط کش OHLCV را در data/wallex_15m_pro_cache کپی کنید.
آخرین بازه مشترک پنج بازار استفاده می‌شود؛ تاریخچه مدام به چهار روز قطع نمی‌شود.
بدون کش، HISTORY_DAYS روز+۷روز warmup دریافت می‌شود. دریافت اول ممکن است چند دقیقه طول بکشد؛ بعداً ادامه داده و دو باکت آخر به‌روز می‌شوند.
درخواست resolution=15 فرستاده می‌شود ولی پاسخ روی۹۰۰ثانیه تجمیع می‌شود؛ اگر پاسخ یک‌دقیقه‌ای باشد نیز همان تجمیع معتبر است.
باکت جزئی حذف نمی‌شود؛ خالی با Close گذشته و حجم صفر پر می‌شود. علت فقدان داده معلوم نیست و «بدون معامله» فرض قطعی نمی‌شود. دانلود جدید bfill از آینده ندارد؛ منشأ پرکردن کش قدیمی از OHLCV تنها قابل بازیابی نیست.
مرز درخواست‌ها غیرهم‌پوشان و timestamp تکراری حذف/رد می‌شود تا حجم دوبار شمرده نشود.

## ۶. ناظر واقعی AI
نامزد ورود، جزئیات تکنیکال، دو نمونه عمق۵سطحی، عمق USDTTMN، روند تتر در صورت وجود، تیتر/خلاصه/لینک۲۴ساعته CoinDesk و Cointelegraph و Fear & Greed به مدل می‌دهد. خبر۳۰دقیقه کش می‌شود.
مدل JSON با EXECUTE_BUY یا SKIP_FAKEOUT، allocation_fraction بین۰٫۵۰تا۰٫۹۲، طبقه خبر، دلیل فارسی و evidence_ids می‌دهد.
این درصد از نقد آزاد است؛ نه اهرم و نه ضریب حجم. حداکثر پوزیشن۲ مطابق منبع است. پیشنهاد پایه۵۵٪ در دو اسلات آزاد و۹۲٪ در یک اسلات آزاد است؛ مدل می‌تواند طبق دامنه درخواستی تغییر دهد.
فیلتر موسوم به AI در منبع، قواعد ثابت است؛ AI واقعی در این بسته ناظر BoxAPI است. مدل اینترنت مستقیم ندارد.
نویز روزمره نباید به‌تنهایی وتو کند؛ یک دیوار منفرد اثبات فشار پایدار نیست. خطای مدل/JSON خرید جدید را متوقف می‌کند، نه خروج محافظتی.
بودجه و تعداد فراخوانی مشترک SHADOW/LIVE در ai_budget.sqlite3 ثبت می‌شوند. هزینه هر تلاش ابتدا رزرو و در صورت وجود usage.cost اصلاح می‌شود. این جای سقف هزینه پنل ارائه‌دهنده را نمی‌گیرد.

## ۷. وضعیت، حسابداری و لاگ
پوزیشن، baseline اجرای سفارش و رویداد در یک تراکنش SQLite ثبت می‌شوند. ثبت تکراری snapshot موجودی و سود را دوباره اضافه نمی‌کند.
کارمزد کوینی از مقدار خالص و کارمزد تومانی از هزینه/دریافت حساب می‌شود. ارز سوم یا داده ناسازگار به‌جای حدس ACCOUNTING_ERROR می‌دهد.
خروجی لاگ:
- logs/decision_logs.jsonl
- logs/decision_logs.csv
- logs/live/ و logs/shadow/
SQLite مرجع اصلی است؛ فایل‌های خروجی از آن بازسازی می‌شوند. ریشه logs خروجی حالت اخیر است و نسخه هر حالت در زیرپوشه خودش می‌ماند.
شناسه سفارش قبل از POST ثبت می‌شود. پس از Timeout حتی با استعلام۴۰۴، POST دوباره فرستاده نمی‌شود. وضعیت UNKNOWN نیازمند بررسی است. خرید جدید مسدود می‌شود؛ خروج سایر نمادها می‌تواند ادامه یابد.
لغو باقی‌مانده پس از۱۵ثانیه تلاش می‌شود و اجرای جزئی حفظ می‌شود. Timeout لغو، موفقیت لغو محسوب نمی‌شود.
تراکنش دیتابیس و صرافی مشترک نیستند؛ exactly-once قطعی شبکه ادعا نمی‌شود.

## ۸. LIVE فقط پس از تأیید نتایج تست‌ها
همه نمونه‌های قبلی ربات باید متوقف شده باشند. قفل این بسته فرایند ربات قدیمی در پوشه دیگری را شناسایی نمی‌کند.
دیتابیس قبلی ساختار متفاوت دارد؛ آن را روی این دیتابیس کپی نکنید. با پوزیشن واقعی باز در نسخه قبلی، مهاجرت را خودسرانه آغاز نکنید. دارایی/سفارش ناشناس مانع خرید جدید می‌شود.
برای فعال‌سازی پس از بررسی باید ENABLE_LIVE_TRADING و ACCOUNT_STATE_ACKNOWLEDGED در env برابر true شوند و CLI تأیید هم بگیرد:

```bat
python -u wallex_live_agent.py --mode live --confirm-live
```

سفارش LIMIT بازارپذیر با قیمت محدود ثبت می‌شود؛ Limit لزوماً Maker نیست. بودجه با کارمزد فعلی Taker و حسابداری با fills واقعی انجام می‌شود.
هیچ‌کدام از بازده‌های اعلامی قبلی، نتیجه تأییدشده این نصب جدید تلقی نمی‌شوند. PnL ثبت‌شده مربوط به اجرای قابل‌حسابداری همین بسته است.

## ۹. خروج اضطراری و پایان
مهلت: جمعه۲۳اکتبر۲۰۲۶،۲۰:۲۵UTC برابر۲۳:۵۵ایران. خرید از۲۲:۵۵ایران متوقف و نقدکردن از۲۳:۲۵آغاز می‌شود.

```bat
python -u wallex_live_agent.py --mode liquidate --confirm-live
```

برای اجرا ابتدا نمونه فعال را متوقف کنید؛ هم‌زمان دو نمونه اجرا نکنید.
موجودی قابل‌فروش پنج بازار مجاز حتی بدون پوزیشن ثبت‌شده فروخته می‌شود؛ سود دارایی بدون بهای تمام‌شده، ساختگی محاسبه نمی‌شود و unknown_cost_basis ثبت می‌شود.
دارایی خارج از پنج بازار خودسرانه فروخته نمی‌شود. باقیمانده زیر حداقل حجم/ارزش، قطعی، سفارش ناشناس و Timeout می‌توانند مانع تسویه کامل شوند. تنها با صفرشدن همه کوین‌ها و بسته‌بودن همه سفارش‌ها LIQUIDATION_CONFIRMED صادر می‌شود.
حد ضرر نرم‌افزاری است، نه stop ثبت‌شده در صرافی. سیستم و اینترنت باید فعال باشند. Ctrl+C فروش نمی‌کند. استاپ و کف سود، قیمت اجرای تضمینی ندارند.
MAX_DRAWDOWN_PCT=0 پیش‌فرض یعنی kill-switch افت کل حساب غیرفعال است تا قاعده جدید به منبع تحمیل نشود؛ DD پایش و حد ضرر هر پوزیشن وجود دارد. عدد مثبت اختیاری سیاست جدید ریسک و نقدکردن را فعال می‌کند.

## ۱۰. بکتست

```bat
python wallex_pro_backtest.py --days 30 --fee 0.003
python wallex_pro_backtest.py --days 60 --fee 0.003
python wallex_pro_backtest.py --days 90 --fee 0.003
```

مقدار fee را مطابق خروجی probe انتخاب کنید. پیش‌فرض منبع۰٫۰۰۱ فقط فرض تاریخی است، نه ادعای Maker واقعی امروز.
منطق ورود/خروج منبع حفظ و مالکیت خروج COMBINED و اولویت بازار اصلاح شده‌اند. مرز داده و bfill نیز ایمن‌سازی شده‌اند.
ورود در Close سیگنال و ترتیب High/Low داخل کندل فرض بکتست است؛ می‌تواند خوش‌بینانه باشد. این روش صف/partial fill یا قیمت لحظه‌ای اجرا را بازسازی نمی‌کند.
MaxDD تک‌ارزی منبع فقط پس از معامله است؛ صفر آن به معنی نبود افت در پوزیشن نیست. MaxDD سبد mark-to-market کندلی است.
جمع بازده تک‌ارزی، سود حساب مشترک نیست. نتایج مالی قبلی بدون اجرای داده مربوط، اینجا تأیید نشده‌اند.

## ۱۱. خروجی برای بررسی

```bat
python wallex_live_agent.py --mode status --state-mode shadow
python wallex_live_agent.py --mode status --state-mode live
python collect_results.py
```

collect_results گزارش‌ها و لاگ‌ها را بدون env و دیتابیس در یک ZIP جمع می‌کند. این اطلاعات معاملات خصوصی است و نباید عمومی شود.
ابتدا نتیجه test_all، سپس probe --test-ai و سپس shadow --once را ارسال کنید؛ LIVE تا بررسی روشن نشود.

## محدودیت استقرار
این بسته SQLite و فضای ذخیره‌سازی پایدار لازم دارد. PostgreSQL و قفل توزیع‌شده پیاده نشده‌اند. LIVE روی فایل‌سیستم موقت Render رایگان عمداً مسدود است؛ با Flask/ping این مشکل داده حل نمی‌شود.
برای ارزیابی رایگان Shadow می‌توان سازگارسازی جدا کرد، اما این بسته ادعای آماده‌بودن استقرار رایگان پایدار LIVE ندارد.
